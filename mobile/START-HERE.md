# Mobile: Flutter setup

The starter app lives in [`solution/`](solution/). It uses Flutter and includes an Android project that can be opened directly in Android Studio.

## Prerequisites

- Flutter stable SDK (current Flutter releases require Dart 3.5 or newer).
- Android Studio with the Android SDK, platform tools, and an Android emulator or USB debugging device installed through **Tools → SDK Manager** and **Tools → Device Manager**.
- A JDK supported by the Flutter/Android Gradle plugin versions generated by Flutter. Flutter normally uses Android Studio's bundled JBR.
- Node.js 24 or newer to run the supplied mock API (see [support setup](../support/SETUP.md)).

In Android Studio, install the Flutter and Dart plugins. In a terminal, verify the toolchain:

```powershell
flutter doctor -v
flutter --version
```

Resolve the Android toolchain and accepted Android SDK license issues reported by `flutter doctor` before building.

## Run the starter app

From the repository root:

```powershell
cd mobile/solution
flutter pub get
flutter test
flutter run
```

Select a running Android emulator/device if Flutter asks. To create or refresh the native Android Gradle project after changing Flutter plugins or Android configuration:

```powershell
flutter create --platforms=android --org com.electricmind --project-name electric_mind_portfolio .
```

Then open `mobile/solution/android` in Android Studio. The generated Gradle project uses `android/local.properties` to locate Flutter and the Android SDK; Flutter normally creates this machine-specific file during its first run. Android Studio can sync and build the generated Gradle project directly. The Flutter root remains `mobile/solution`; use Flutter commands for app run/debug and hot reload.

## Start the mock API

In a separate terminal at the repository root:

```powershell
node mobile/mock-server.mjs
```

Check `http://localhost:4001/health`. Android emulator networking reaches the host at `http://10.0.2.2:4001`; physical devices use the computer's LAN address and require `node mobile/mock-server.mjs --host=0.0.0.0`. The API contract, field units, response types, routes, scenarios, and error cases are documented in [API-CONTRACT.md](API-CONTRACT.md).

The mock uses local HTTP. For Android development builds, the generated manifest allows cleartext traffic. Do not use that setting in a production configuration.

## Current starter scope

The Flutter app is a minimal Material 3 shell with a Portfolio Overview placeholder. The portfolio screens, persistence, authentication, offline reconciliation, notifications, native share, account selection, and charts remain to be implemented from [REQUIREMENTS.md](REQUIREMENTS.md). The mock API needs no credentials.
